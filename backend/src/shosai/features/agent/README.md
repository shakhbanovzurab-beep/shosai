# agent

Leo's core: a person's conversations with Leo in Personal and in each workspace, the run that answers a turn — reading through every slice's tools under the one access policy and naming each source with its space — and the Action Gateway, the only path by which Leo changes anything, after the person approves a card that says exactly what will change. The slice also owns Settings › Leo, the rating of answers, the skills store, the native model proxy of the shipped desktop clients and Leo in the admin panel. The cabinet's feature is `leo` (SLICE_MAP §4.3).

- Plan: [docs/plan/slices/agent.md](../../../../../docs/plan/slices/agent.md). Decisions: AG-D1…AG-D14 in the plan and [ADR 0068](../../../../../docs/adr/0068-leo-agent-slice.md); the design is the [Leo architecture](../../../../../docs/design/leo/ARCHITECTURE.md) with ADR 0023–0033.
- Public surface: `contracts` (`ActionProposals` for a slice's planned write without a model round; the ports agent needs — `TurnRouter`, `FrictionJudge`, `MemoryRecall`, `ProfileFacts` — and `SkillReader` for studio) and `contracts.events` (`agent.turn.completed`).
- Turns run on the dedicated `agent` queue's workers; the API admits, commits and streams them from the run's log in Valkey (AG-D12). LangGraph is only the frame of a turn (AG-D14).

## HTTP

- `GET` and `PATCH /v1/agent/settings` — Settings › Leo, saved field by field and answered whole (`channels/http/settings.py` over `application/preferences.py`); the four `leo_*` switches of the native `/v1/auth/me` come from the same rows through identity's `ME_CONTRIBUTIONS`.
- `/v1/agent/threads*` — a space's threads by cursor, created at the first question under an `Idempotency-Key` and untitled until it names them, renamed, deleted with their conversation, and a thread's history newest first (`channels/http/threads.py` over `application/threads.py` and `application/history.py`). Every read puts the person's active memberships into its statement, so a departed workspace's threads vanish at once (AG-D3).

## Turns and runs (step 5a, AG-D12)

- `POST /v1/agent/threads/{id}/turns` → `text/event-stream`, `GET /v1/agent/runs/{id}/events` (resume after `Last-Event-ID`), `POST /v1/agent/runs/{id}/cancel` (`channels/http/turns.py`).
- The API admits a turn (`application/turn_start.py`): the same `Idempotency-Key` answers its run; consent in the Russian home, the plan's tokens (billing's `TOKEN_ALLOWANCE`), 20 turns a minute, two runs a person and the fleet's capacity (`infrastructure/fleet.py`: 48 runs for each agent worker alive) are checked before anything is written; the thread's lease (`infrastructure/thread_lease.py`) or a superseding stop; one transaction writes the question and the run (`application/turn_commit.py`); `run.started` goes to the run's log and the run to the `agent` queue (`application/turn_task.py`).
- An agent worker drives it (`application/run_engine.py`, its steps in `application/run_steps.py`): the frame `context → model ⇄ tools → respond` in LangGraph (`infrastructure/turn_graph.py`, the only module that imports LangGraph), the model's text written to the log at most every 100 ms (`application/model_stream.py`), one final transaction that only the worker or the sweep wins, then the terminal event. One task per worker reads stop requests twice a second and renews leases and counts every 10 s (`application/run_registry.py`); the worker counts in the fleet while it takes tasks (`application/fleet_presence.py`, a queue companion).
- The context builder v1 (`application/run_context.py`, `domain/context.py`): the policy and the profile core (name, time zone, the answer's language and length) open every turn byte for byte; then the thread's summary, the newest messages before the question within 5 000 tokens, and last the time to the minute in the person's zone, the page and its subject — told through its owner's reader by its id, someone else's words wrapped and labelled and tainting the run (`application/surface_digest.py`) — with the question. "Regenerate" and "Edit" answer the thread's last question again and replace only its answer (`application/turn_commit.py`, `application/run_end.py`).
- After a turn (`application/after_turn.py`, on the slice's own `agent.turn.completed`): the thread's title by `AGENT_UTILITY_MODEL` after its first answer unless the person renamed it, and the folding of its oldest turns into the summary — which always opens with the first question — once the unfolded messages pass 70 % of the recent segment's cap (`application/thread_care.py`); both best effort and conditional on what they read.
- Telemetry (`application/run_telemetry.py`, `infrastructure/run_metrics.py`): the run's row keeps its model, tokens, cost, the wait for the first word and the platform's own time; spans `agent.run` and `agent.context` around the port's `ai.call`; `shosai_agent_*` metrics with closed labels; the objectives of `objectives.py` (99 % of turns without a platform failure, the platform's time under 0.5 s for 95 % of EU turns).
- The run's log is a Valkey stream with ids `0-<n>` (`infrastructure/run_log.py`); an API process follows every log its clients read with one blocked `XREAD` (`infrastructure/log_tail.py`), and a log silent for 45 s yields the end the run's row recorded (`application/run_streams.py`).
- A minute's sweep ends `running` runs without their lease as `process_lost` (`application/lost_runs.py`); the queue never re-runs a turn.
- The model is `AGENT_STANDARD_MODEL` with an optional fallback (`settings.py`, AG-D4); the policy is English text (`infrastructure/prompts.py`); LangSmith tracing refuses to start.

## Tools (step 6)

- Every slice's bound tools are in core's catalog; `application/tool_registry.py` reads it on the first turn and groups them by toolset in a fixed order — `core`, `notes`, `tasks`, `files`, `account`, then the rest — at most eight to a toolset, each name spelled for the wire (`notes__search`). Reads, cabinet actions and writes are offered — a write's call becomes a card (Action Gateway, below); a tool behind a switch the person turned off (the payload carries those left on — memory's `MEMORY_SWITCH` while memory's `PROFILE_FACTS.enabled` says it is on) or an entitlement the plan lacks never is.
- Routing (`application/tool_offer.py`, AG-D7) runs in the context's transaction: the core toolset, the page's section and subject, the toolsets the thread's last three runs called, then the others while segment 2's 4 000 tokens hold; the rest are named in `core.load_toolset`'s description, and a call of it adds one from the next round (`shosai_agent_load_toolset_total`, a ticket above 5 % of turns). The run's row keeps `routing`: selected, reading, deferred, loaded, used, wrote, routed and whether a router was asked.
- Leo's own toolset (`channels/agent_tools.py`): `core.read_result` pages a kept result by bytes, re-checking its spaces on every read (AG-D3, `application/result_pages.py`); `core.load_toolset`; `core.navigate`, which sends the cabinet `client.action {navigate: {to}}`.
- A round (`application/tool_round.py`): up to eight calls in parallel, the rest refused, and the last call of an answer the token limit cut refused too; a tool not offered or arguments its schema refuses never run; each call within its timeout and the turn's deadline, through a bulkhead one below the process's pool; a failure is the model's to explain. A result over its budget is kept whole and read as a digest that names each cut list's size (`domain/digests.py`); one with a provenance is wrapped with the run's boundary and raises its taint; a page of a kept result takes its tool's label. Each call that runs is a step in the stream and on the answer. What the model reads back is registered English (`application/tool_answers.py`, `infrastructure/prompts.py`).
- Sources (AG-D1, `application/run_sources.py`): a result names what it rests on (`ToolResult.sources`); the run numbers each new source in arrival order, the model reads the numbers beside the result as `sources` and cites `[n]`, and the stream sends the whole list after each step that grew it. A source is named by its space — the workspace's name, or Personal in the answer's language (`domain/spaces.py`) — read once per run; one from a workspace the person is not in is dropped. The answer keeps its sources (with their workspace); a later turn reads an earlier answer with what its numbers stood for, as kinds and ids only. Notes, files and tasks name theirs; a colleague's personal meeting or file shared into a workspace is named by that workspace (workspaces' `AccessPolicy.shared_into`).
- Rounds: from the fifth the model is asked to conclude; the tenth has no tools. Each round is its own provider call and effect key; the run's row sums them (`application/run_work.py`). The rounds are kept as rows before the answer — the model's message with its calls, then each call's answer — for the run's record; later turns read only questions and answers (Leo §7.3).

## Action Gateway (step 9a, Leo §8.4)

- A write tool is offered like any other; its call never runs in the round (`application/write_proposals.py`): the slice's `plan` freezes the targets and `preview` describes them, within the tool's timeout, and a refusal is the model's to explain. A planned write is stored as an action — one item, the plan and the preview, the arguments' names with hashes, friction by AG-D7's rule (a warning when the run read text someone else wrote or the write cannot be undone) — a card the rule left standard is put to a bound `FrictionJudge` (decisions' `action.friction`) with the person's question of the turn and the card as they will read it, and takes a warning only when the judge asks for one (`application/friction_judging.py`) — the run's taint and its labels, a nonce and an hour — with its audit row (`application/action_proposal.py`); `action.proposed` carries the card (`application/action_cards.py`) and the run pauses (`run.paused`; the run's row `paused`, its answer so far kept, its log held past the card's hour). A second write of the same round is refused until the person decides.
- Cards (step 9b1, `application/action_cards.py`): an action is rendered as the cabinet's `LeoProposal` in the person's language (their profile's) — the title and labelled fields from the wording its slice declares beside the write's spec (`ToolSpec.previews`, the 16 languages checked by `tests/features/agent/test_card_words.py`), the space (Personal, or the workspace by name from the plan's `org_id`), the origin, reversibility, warning, taint label, whether the run read text giving Leo instructions (`suspicious`), state, times and nonce — the same in `action.proposed` and `action.updated`, the decisions' answers, the inbox and the history, where an answer and a server note carry their cards in `actions`. A preview its slice has no words for is refused at proposal. The inbox (`application/action_inbox.py`): `GET /v1/agent/actions?status=&cursor=&limit=` newest first — `proposed` only within the card's hour — and `GET /v1/agent/actions/{id}`, both as the person.
- `POST /v1/agent/actions/{id}/approve|reject` with the card's nonce (`channels/http/actions.py`, `application/action_decisions.py`): one conditional update of a `proposed` card of the person within its hour; a card found past it expires there. An approval is audited and sent to the `agent` queue (`agent.run_action`); the answer waits up to 20 s for the end. A rejection closes the card and its run.
- Execution (`application/action_execution.py`): the worker claims the approved action once, marks each item `executing` in its own commit, then calls the slice's `execute` with the key `action:index` — the slice applies it once in its own transaction with `agent.action_item.executed` (`ActionItems`); a typed refusal fails the item, a timeout or an unexpected error leaves it `outcome_unknown`, never retried. The action ends `succeeded`, `partially_succeeded`, `failed` or `outcome_unknown`.
- Every end adds a server note to the thread — empty text for the cabinet, the outcome in registered English for Leo (`application/paused_runs.py`) — and puts `action.updated` (with the query domains the write invalidates) on the run's log. An action that ended after an approval hands its paused run to the `agent` queue (`agent.resume_run`): the worker takes it back while its frame is kept, its log is alive and its thread's lease is free, moves it `paused → running` with a condition (`application/run_resumption.py`), rebuilds the conversation from the database — the context, the run's rounds before the card, the note (`application/run_earlier.py`) — and the model writes the epilogue in the same run and stream; the answer, with the epilogue, moves after the note, and the run row adds the epilogue's rounds, tokens and time to its own. A rejected or expired card closes the run `completed` (`decided`); a lost frame or a hand-over that cannot happen closes it `checkpoint_lost` (`application/run_close.py`); a new turn on the thread closes its paused runs (`new_turn`) and their cards stay decidable, with a note.
- A slice's write without a model round (AG-R2, step 9b2, `application/proposal_port.py` binding `ACTION_PROPOSALS`): the calling slice names a write tool and its arguments for the person; they pass the tool's schema, its slice plans and previews the write as for a model's call with no untrusted text before it, and one transaction in the person's scope stores the card under the caller's `origin_key` (the same key returns the same card), adds it to the answer's `action_ids` and renders it in the caller's language. Refusals are `ProposalRefusedError` with the tool's error code. The card is decided, expired, executed once and audited like a turn's; with no run to resume, its end is the thread's server note.
- Artifacts (AG-R1, step 9b2): a read tool's `ToolResult.artifacts` reach the stream as `artifact {kind, ref, alt, …fields}` — a team chat's digest by its id with `workspace_id` and `chat_id` — and stay with the answer (`agent_messages.artifacts`), which the history returns; the thread keeps the reference only.
- The frame (`infrastructure/turn_graph.py`, AG-D14): LangGraph's interrupt pauses the turn in an `approval` node, and `Command(resume=…)` goes on from there in another process; the state holds the turn's terms and references only. Our saver (`infrastructure/turn_saver.py`, fields in `turn_frame_fields.py`) keeps each run's latest checkpoint in one Valkey hash `agent:run:{run}:ckpt` — written after every step in the background, only the channels a step changed, the pending writes by checkpoint — for at most the card's hour and a quarter; the engine deletes it at the run's end. A Valkey that does not answer costs the epilogue, never the card.
- The minute's sweep (`application/action_sweeps.py`): a card past its hour expires; an approval no worker claimed is handed over again after a minute and fails `not_started` after ten; an action whose executor fell silent past five minutes ends with what is known — an item that started is `outcome_unknown`; a run still paused five minutes after its action ended lost its hand-over and closes. Deleting a thread supersedes its cards and cancels its paused run.
- Audit (`agent_audit`): the gateway writes `proposed`, `approved`, `rejected`, `expired`, `superseded`, `failed` and `outcome_unknown` rows; `executed` rows come from the slices' events (`application/action_audit.py`, once per delivery). The hourly `agent.check_actions` (`application/action_invariants.py`, as the sweep role) reads the last two hours' `executed` rows and sets per home the items executed twice and those without `approved` (L-N5): both page above 0 (`objectives.py`). Metrics: `shosai_agent_actions_total{origin, outcome}`, `shosai_agent_approval_seconds`, `shosai_agent_action_execution_seconds`, `shosai_agent_approved_actions_total{result}` — the objective: an approved action carried out or refused with a code within 30 s in 99 % — `shosai_agent_run_resumes_total{outcome}`, `shosai_agent_items_executed_twice{home}`, `shosai_agent_items_executed_unapproved{home}`.
- Routing `rules_v2` (AG-D7, refined for writes): core, the page's toolsets and those the thread proposed writes to come whole, the reads of those it read from always; then every other toolset's reads while segment 2 holds, then their writes. A toolset offered for reading only is named in `load_toolset`, whose loading brings its writes. When the rule cannot offer a toolset even for reading, a bound `TurnRouter` (decisions' `turn.route`) ranks the others while the context is read — the first model request waits for it at most 400 ms — and the ones it found needed fill the room first; they stay for the thread's next three turns, and the router hears which toolsets the run called (`application/route_ranking.py`, `routing.routed`). Today every toolset's reads fit, so no turn asks it.

## Voice (LEO-voice step 4, ADR 0070)

- `VOICE_TURNS` (`contracts/voice.py`, `application/voice_turns.py`) is what capture's voice mode uses of the agent. `open` refuses the operator (`voice_not_available`), a thread of another space or person (`thread_not_found`), the RU home without consent (`consent_required`), voice mode switched off in Settings > Leo (`voice_mode_off`) and spent tokens, then gives a conversation on the named thread or a new one: the voice model's instruction in registered English with the answer language (`infrastructure/voice_prompts.py`), and the page's tools from the same routing — whole, within 12 000 tokens of schemas instead of the text turn's 4 000, and without `core.load_toolset` and `core.navigate`: a session fixed at its start cannot load a toolset or open a page later, so a write it may need must be there from the start.
- A tool call runs through the text turn's round (`ToolRound` with `application/voice_emitter.py` in place of the run's log): a read under the access policy with its sources, a write as a card that never runs; steps and cards reach the socket. Calls and records of one conversation go one at a time.
- Each exchange is a run of channel `voice` (`application/voice_records.py`): its row is written before the first call so a card has its run; at the exchange's end one transaction writes the person's phrase as the question and Leo's words as the answer — `stopped` when the person interrupted — with the steps, sources and cards, moves the thread's activity, titles a new thread and puts `agent.turn.completed` in the outbox. An exchange with nothing said and no call writes nothing.
- Approval by voice (step 8, Leo §8.4, Q-6, `application/voice_approval.py`): a card made in a voice exchange is read back from the server's rendering — the words the person also sees — and the tool's answer tells the voice model whether it may go by voice. Only a standard card (reversible or compensable, after no one else's text, one item) may, and only when both hold: the model calls the voice-only `core.confirm` for a card read back in this conversation, and every bound `VOICE_APPROVAL_JUDGE` (decisions' `voice.approval`) finds the person's phrase, as the server transcribed it, a clear yes to what was read back. Then the card goes the screen's way — one conditional update, the audit, the worker — with `approved_via = voice` (migration `fb74f9126b03`, both homes). No judge bound, a judge in doubt, an empty phrase, a card with a warning, one not read back here or no longer waiting: nothing is done and the card stays on the screen; without a judge `core.confirm` is not even offered.

## The operator's pictures (step 16b2, AG-D5, AG-D10)

- `images.draw` (`application/platform_images.py`, the operator's own toolset `images`, offered to the operator alone like `platform`) asks `AGENT_IMAGE_MODEL` (OpenRouter, priced per image token by F6's sync; without it the tool answers `unavailable`) for a picture as an expensive interactive call paid by the platform's `admin_assistant`. A picture of another type than PNG, JPEG or WebP, past 10 MB or 40 megapixels, or whose bytes are not the type named (read from the header with Pillow, no pixel decoded) is refused and nothing is stored.
- The object goes to `platform/agent/images/{id}` in the EU home's bucket (ADR 0055) and its pointer row to `agent_images` by the run that drew it (revision `173ed4677079`); the answer carries an `image` artifact by reference with its width and height, so the panel holds its place. The admin reads it at `GET /v1/admin/agent/images/{id}`: a 302 to a 15-minute link of the bucket, never cached, 404 `image_not_found` for a picture that is gone.
- A thread's deletion deletes its runs' pictures; a trigger puts their keys into `agent_image_releases`, and `agent.release_images` (every 15 minutes, as the sweep role) deletes the objects, then the release rows.

## Evaluation (step 8, AG-D8)

- The scenarios (`infrastructure/eval_data/scenarios.json`): a question on a page in all 16 languages, what each tool it needs answers — checked against the tool's real output schema — the scripted model's rounds, and what a good trajectory does: the tools, the arguments that matter, the words and citations of the answer. The injection corpus (`eval_data/injections.json`) puts hostile payloads into every channel of untrusted text: each read tool with a provenance and the page's meeting, task and file; a test fails when a new untrusted tool has no carrier.
- A scenario runs through the real turn (`application/eval_runner.py`): the same starter, engine, context, routing, rounds, wrapper and sources, for a person who exists only for the run. The ports around that person answer from the scenario (`application/eval_world.py`); the slices' tools are their real specs answered by the scenario (`application/eval_stage.py`); the model is the scripted double or a real one behind a recorder (`application/eval_model.py`). The person's rows are erased after the run through the erasure handlers; runs and effect keys expire as for any deleted account.
- CI runs the deterministic suites on every push (`tests/features/agent/eval/`, over `application/eval_suites.py`): each scenario's trajectory exactly as scripted, the context within its segments' caps and a first round within 12 000 tokens in all 16 languages, the cached head and tools byte-identical on a second turn, each scenario's model calls and tokens within 10 % of `eval_data/cost_baseline.json`, and every injection case without a write or egress that ran, a navigation outside the cabinet, an untainted probe or a payload outside its wrapper.
- `shosai agent eval` (development only; `composition/agent_eval_command.py`) runs the live suite: each scenario in each language through `AGENT_STANDARD_MODEL`, a judge (the same model, or `--judge-model`) grading language, grounding and help (`application/eval_judge.py`, prompt in `infrastructure/eval_prompts.py`), and the scores against `eval_data/live_baseline.json`: no suite more than 3 points lower, tool choice at least the baseline, every language at its floor (`domain/eval_report.py`). `--scripted` runs the deterministic suites with no key. The report lands in `agent-eval/<UTC time>/` (`report.md` for the change's record, `report.json`); `--record REASON` adds the new baseline to copy into `eval_data/`.

## Departures

`application/departures.py` (AG-D3): `workspaces.member.removed` marks the departed person's threads of the workspace to be erased in 7 days, as that person (ADR 0067); the hourly `agent.purge_departed` erases the due ones or, for a member active again, clears the mark; `workspaces.workspace.deleted` erases the workspace's threads at once, person by person.

## Tables (each home, revisions `a6c8e2f4b917`, `9a43ed077e60` and `92bc6bf92c5e`)

Every table is personal by nature: row-level security admits the person's own rows only (ADR 0053).

- `agent_threads` — a conversation in one space (Personal, a workspace, a hub; the database keeps the scope naming exactly its space), its title (null until the first question), summary and `erase_after` for a departed workspace (AG-D3).
- `agent_messages` — a thread's rows in monthly partitions kept with the thread: questions, answers (with a status), tool rounds and their digests, server notes; deleted with the thread.
- `agent_tool_results` — tools' whole outputs with the spaces of their sources, read for 30 days, partitions dropped after two months.
- `agent_runs` — a run's status and telemetry (ids, numbers, codes), monthly partitions kept four months; `ended_at` exactly when it is over.
- `agent_runs.taint` — how far untrusted text reached the run when it ended (none, external, suspicious); revision `a1a96ace53e1`.
- `agent_actions` — a proposed write with its planned items (1–20), friction, taint and expiry; resolved exactly when over; one card per origin key (AG-R2); a deleted thread leaves its actions in the inbox.
- `agent_audit` — append-only for the application (insert and select), monthly partitions kept 12 months, codes only; the sweep role reads it for the hourly check (`92bc6bf92c5e`).
- `agent_settings`, `agent_skills`, `agent_feedback`, `agent_eval_cases` — Settings > Leo (absent while the person keeps the defaults), installed skills pinned to a commit, one rating per answer, and the cases a rating made with consent; ratings and cases go with their thread.
- `application/account_data.py` — the person's rows are exported, erased (with the Valkey keys of their recent runs and threads, `infrastructure/run_keys.py`) and copied to another home; runs and the audit expire by their partitions; tool results and actions are short-lived and not copied.

## Rules the domain holds

- `domain/threads.py` — a thread's scope (Personal, a workspace or a hub), titles of 1–120 characters, a question of 1–4 000 characters with up to five attachments, "Regenerate" and "Edit" on the last question only; a departed workspace's threads erased 7 days after the departure unless the membership is active again (AG-D3).
- `domain/runs.py` — a run is running, paused or ended once (completed, failed with a code, cancelled); deadlines, the thread lease, the event log, two runs per person and 48 per worker.
- `domain/actions.py` — an action's machine (Leo §8.4): every transition names the status it expects, so the store applies it as one conditional update with one winner; items end with honest partial success, and a cut item is `outcome_unknown`, never retried; a proposal expires after an hour; the cabinet sees an approved action as executing and a superseded one as expired.
- `domain/budgets.py` — the context's eight segments with their caps, from the most static to the most volatile; four rounds before Leo is asked to conclude, ten at most, eight calls a round; token estimates from UTF-8 bytes in every language; the recent window cut by tokens; compaction past 70% of it.
- `domain/wrapper.py` — untrusted text between a per-run boundary and a closing marker, labelled from a closed set and escaped so it holds no `<<`; the run's taint only grows, and external text makes egress wait for a card. Every piece wrapped into a run — a tool's result or page, the page's subject, the person's attachments (`file:own`) — is put to a bound `InjectionJudge` (decisions' `content.injection`) the moment it is wrapped, off the round's path; the judgements are awaited, each at most 400 ms, before a write's card and at the run's end, and a positive one makes the run suspicious: its card says so (`suspicious`) and the run's row keeps its final taint (`agent_runs.taint`) for memory (`application/injection_watch.py`). The person's own words carry no label and are never judged.
- `domain/sources.py` — the run's sources numbered in arrival order; a number never changes and the same place in the same thing keeps its number (AG-D1).
- `domain/stream.py` — the stream's closed vocabulary, monotonic numbers, steps opened and closed once, exactly one terminal event.
- `domain/routing.py`, `domain/friction.py` — the deterministic rules beside `decisions`' ports (AG-D7): core, the page's and the thread's recent toolsets, then others while segment 2 holds; a warning card for a tainted run or an irreversible write, never less than the rule. Every card's end — approved, rejected, expired — is told to the friction judge, so its judgements can be measured (`CardEnd`).
- `domain/preferences.py` — Settings › Leo with everything on by default, `auto` model and language, the switches gating tools, the four switches of the native `/v1/auth/me`.
- `domain/feedback.py` — a rating of an answer; a rated turn kept as an evaluation case only with `improve_models` consent and no workspace source, the name masked, a year at most (AG-D13).

Core's tool contract gained, for this slice (ADR 0068): `ToolResult.sources` and `.artifacts` (`core/agent_tools/sources.py`), `ToolSpec.step_detail` and a write's `ToolSpec.previews` — its wording of the preview keys in the 16 languages, rendered by `core/agent_tools/previews.py` into the card's title and rows.
