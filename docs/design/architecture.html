Shosai — Target Architecture

EU compute plane · two data homes (Russia, EU) · B2C + B2B · design point 10 000 DAU, 2 600 concurrent meetings

Live meeting ①–⑤

  • • ① Client connects through the edge
  • • ② Edge picks the least-loaded WS process
  • • ③ WS streams audio to the AI provider
  • • ④ Line gets seq, lands in the durable Redis queue, then on screen
  • • ⑤ Queue drains to the home DB in batches ≤ 500 ms

Placement and residency

  • • One compute plane in the EU; AI reached directly
  • • Two data homes: Russia and EU, PostgreSQL each; one S3 bucket in Russia for both
  • • The access token carries the home; directory only at sign-in
  • • One account per person; a workspace and its members live in one home
  • • Derived copies of Russian users in the EU — accepted
  • • Files of the EU home in the bucket in Russia — accepted, legal review

Companies (B2B)

  • • org_id + access level on meetings, notes, folders, knowledge
  • • One access policy; rights never cached
  • • Row-level security as the second line
  • • Search and Leo re-check every hit in the DB
  • • Audit event in the same transaction; invoices by bank statement

Not drawn

  • • Redis LRU cache container (loss is harmless)
  • • Observability (Grafana stack): Prometheus (metrics, 30 d), Loki (logs, 14 d), Tempo (traces, 7 d), Grafana; OpenTelemetry Collector; probe outside the plane
  • • Delivery: GitHub Actions → registry → staging → plane
