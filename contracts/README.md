# Contract baseline and compatibility harness

Shipped native clients must keep working against v2 without an update (target architecture nfr-12), and their code is outside the rewrite. This directory is the guard: a frozen copy of the draft's external contract, the list of who uses each part of it, and a harness that tells a v2 slice which parts it has broken.

Work package D1 produced it. See [docs/plan/REWRITE_PLAN.md](../docs/plan/REWRITE_PLAN.md).

## What is here

| Path | What it is | Source of truth |
|---|---|---|
| [draft/openapi.json](draft/openapi.json) | OpenAPI 3.1 document of the draft, generated from the draft application | generated by `tools/` |
| [draft/routes.json](draft/routes.json) | Every route of the draft in production shape, including pages, links and WebSocket routes that OpenAPI leaves out | generated by `tools/` |

The draft was captured at commit `589917e84` of `github.com/shakhbanov/whisperer` on 2026-10-01. The two `.md` files are rendered from the JSON. Edit the JSON and run `uv run shosai-contracts render`; a test fails if they drift apart.

## What the baseline says

### Who uses the API

| Client | Status | Counts for compatibility |
|---|---|---|
| macOS app 1.4.5 | working, DMG, no auto-update | yes |
| Windows app 1.4.5 | working, installer, no auto-update | yes |
| Linux app 0.1.0 | frozen by the owner (2026-10-01) | no; calls recorded for reference |
| WhispererKit (shared Swift package) | inside the macOS app (and the frozen Linux and unshipped iOS apps) | yes, except its Hub, Knowledge, Leo, Proactive, Rooms, Search and Workspace modules, which the macOS app does not use |
| iOS app | no: never released | no; calls recorded for reference |
| `pwa-app/` | no: never deployed | no |
| HubSpot marketplace app | yes | yes (OAuth redirect URI) |
| Obsidian vault plugin | yes, outside the draft repository | yes (`/v1/knowledge/vault/*`) |
| Web cabinet and public site | replaced by v2 | no: they change together with v2 |

### Classes

Each of the 588 production routes and each WebSocket frame has one class:

| Class | Count (routes) | Meaning | What a slice must do |
|---|---|---|---|
| `native` | 34 | Used by a working native client (macOS, Windows) | Keep wire-compatible |
| `external` | 74 | Webhooks, OAuth redirect URIs, MCP, the Obsidian plugin, links in emails and shared links, public site URLs | Keep wire-compatible |
| `web` | 383 | Only the draft web frontend and public site | Free to change together with the v2 frontend (visual parity is D2's job) |
| `unused` | 93 | No live consumer found, including routes reached only from dead code | Not carried over unless D4 keeps it |
| `excluded` | 4 | The draft's own probes and `/metrics` | Not checked; F1 and F5 define their own |

Four WebSocket endpoints carry native frames: `/v1/ws/realtime`, `/v1/ws/sessions/{session_id}`, `/v1/ws/voice-translate` and `/v1/ws/user` are `native`; `/v1/ws/voice`, `/v1/subtitles/stream` and `/v1/ws/demo-translate` are `web`.

A route is `native` as soon as live code in a working app calls it. A call site that is unreachable (dead code, or a WhispererKit module the macOS app does not use) is recorded with its evidence but does not raise the class.

### Owner decisions (2026-10-01)

- **Working clients are macOS 1.4.5 and Windows 1.4.5.** The Linux app 0.1.0 is a frozen project and does not constrain v2.
- **The rewrite does not touch the clients.** v2 adds no aliases for calls that fail in the draft (see below).
- **Dead code is not carried over.** A call that only dead code makes does not keep a route alive; the evidence is stored with the call site (`"dead"` in `consumers.json`, "dead code" in `consumers.md`). This made `POST /v1/ai/transcribe` `unused`: macOS reaches it only through `LiveTranscriber.init(config:backendBearer:)`, which nothing calls (the app always transcribes over `/v1/ws/realtime`), and Windows never calls `BackendAIClient.TranscribeAsync`. Simultaneous translation uses `/v1/ai/voice-translate/*` and `WS /v1/ws/voice-translate`, which stay `native`. Six web-only routes reached only from unused wrappers became `unused` the same way.

### Rules that no schema can express

These were found in the clients' code. The harness cannot check them; the slice that owns the area, and F4 and M2 for the host, must.

- **TLS pinning.** macOS (through WhispererKit) and Windows accept `whisperer.one` only if its certificate chain contains the public key of the Let's Encrypt YE1 intermediate or of ISRG Root YE (`shared/WhispererKit/Sources/Core/Config.swift:174`, `windows-client/src/Whisperer/Network/CertificatePinner.cs:41`). The two code bases hash the key differently (`shared/WhispererKit/Sources/AppSecurity/CertificatePinner.swift:24`), but they pin the same keys. The v2 certificate for `whisperer.one` must therefore keep coming from Let's Encrypt on that chain. A certificate from any other chain cuts off every shipped client.
- **Base URL.** Clients call `https://whisperer.one/v1/...` without a trailing slash.
- **Unknown API paths answer 404 with JSON.** macOS probes `/v1/scripts` and treats 404 as "feature hidden". An HTML page or a redirect for an unknown `/v1/...` path breaks that.
- **Error bodies.** Native clients read `{"detail": "<code>"}` (sign-in) and `{"detail": {"code": "..."}}` (voice translation, audio upload; a string is also accepted). The v2 error envelope is still undecided (CLAUDE.md, "Undecided"). Whatever it becomes, it must keep `detail` in this shape on `native` routes.
- **Values.** Dates are ISO-8601 with a time zone; one without breaks decoding of the whole response. macOS sends upper-case UUIDs in paths and in `sid`, so ids must be matched case-insensitively. Meeting note and import responses use camelCase keys (`draftMarkdown`, `jobId`, `fileName`, `meetingId`).
- **Desktop sign-in.** Desktop logins send `X-Client-Kind: desktop` and `captcha_token: null`, so they must stay exempt from the captcha. Cookie refresh sends `X-CSRF-Token` copied from the `meetassist_csrf` cookie.
- **Legacy paths.** macOS opens `/cabinet/leo?reminder=<id>` with `?` encoded as `%3F`, and the web opens `/studio/{id}`, `/rooms/{id}`, `/meetings/{id}` and `/cabinet?paid=1`. All of these rely on the top-level fallback redirecting into `/app/...` after decoding the path.
- **WebSocket authentication.** Clients send the token in `Authorization: Bearer` or as the `whisperer-bearer, <token>` subprotocol, never in the query string. On `/v1/ws/realtime` an HTTP 401 or 403 on the handshake makes shipped clients **stop reconnecting**.

### Where the draft and the target architecture differ

§10 of the target architecture defines interfaces the draft does not have. v2 adds them **next to** the draft's, never instead of them, and only additively on shared endpoints:

- **Live capture (`/v1/ws/realtime`).** The draft has no protocol version in `hello`, no `seq` replay, and no `transcription.busy` or `server.shutdown` frames; resume is per meeting via `transcript.restore`. v2 may add these as new optional fields and new frame types. WhispererKit and the Windows client ignore unknown frame types. The existing frames stay as they are.
- **Full plane → 1013.** In the draft any close before `accept()` reaches the client as HTTP 403, and shipped clients treat 403 as an authentication failure and stop reconnecting. v2 must therefore accept the socket and then close it with 1013. Rejecting the handshake would strand those clients.
- **End meeting, upload, runs.** `POST /v1/me/sessions/{id}/end`, `POST /v1/me/uploads` and `GET /v1/me/runs/{id}` are new. Shipped clients stop a meeting with `PATCH /v1/sessions/{id}` and upload recordings through `/v1/me/sessions/{id}/audio/*`; both stay.
- **Pagination.** `GET /v1/me/sessions` pages by `limit`/`offset`, and macOS uses it. It stays a bare array with `limit` (1–200) and `offset` over the person's newest 200 meetings and gains no cursor; the cabinet's cursor list is `GET /v1/meetings` ([meetings plan](../docs/plan/slices/meetings.md) MT-D1).

### Calls that fail today

Some client calls match no route (full list in [draft/consumers.md](draft/consumers.md#client-calls-that-match-no-draft-route)). They fail in the draft too, and by the owner's decision v2 does not add aliases for them:

- Windows saves meeting notes to `/v1/sessions/{id}/note[/draft]`; the route is `/v1/me/sessions/{id}/note[/draft]`.
- WhispererKit's Workspace module calls `/v1/storage/download-url/{id}`, `/v1/storage/content/{id}` and `POST /v1/storage/folder` without `me/`. Only the unshipped iOS app reaches these calls.

## Using the harness in a slice

The harness compares v2 artifacts with the baseline within a scope: owning slices, consumer classes and path prefixes. It starts from the draft: every draft route and frame in scope must exist in v2 in a compatible form. New v2 routes are never findings.

The backend's gate checks the `native` class only, whatever slice serves the route, with `--served-only`: a native route v2 serves must keep its contract, and a native route not served yet is listed in the report instead of failing (owner's decision OD-2 of the [F1 audit](../docs/plan/audits/F1-audit.md)). The backend records that list in `backend/tests/composition/native_routes_not_served.json`; it must be empty before cutover (M2). External callbacks are not gated: each slice designs its own and re-registers the URL with the provider.

### Produce the v2 artifacts

| Artifact | Format | Where it comes from |
|---|---|---|
| OpenAPI | OpenAPI 3.x JSON | `app.openapi()` of the v2 API process |
| Route snapshot | JSON array of `"METHOD /path"` strings, WebSocket routes as `"WS /path"` | the v2 route table (the same snapshot §10 requires) |
| WebSocket catalogue | `whisperer-websocket-catalogue/1`, below | exported from the v2 frame definitions |

Any of the three can be left out; that part of the check is then skipped, and the report's coverage line shows it.

### Run it from the command line

```bash
uv run --project contracts shosai-contracts check \
    --openapi build/openapi.json --routes build/routes.json --websocket build/websocket.json \
    --class native --served-only
```

`--slice` (repeatable) limits the check to routes owned by the slice; ownership is the `slice` field in `draft/consumers.json`, the draft-era cut of D4. `--class` (repeatable) limits it to a consumer class, `--path-prefix` by path. `--served-only` checks only the endpoints the candidate serves and lists the others as not served yet. A WebSocket endpoint found in the route snapshot but missing from the WebSocket catalogue is reported as `ws.not_in_catalogue`: its frames cannot be verified until the slice exports its catalogue. `--format json` gives a machine-readable report, and `--min-severity warning` hides info lines. The exit code is 0 when there are no errors, 1 when there are, and 2 when the input is invalid.

### Run it from a v2 test

Add the harness as a development dependency of `backend/`:

```toml
[dependency-groups]
dev = ["shosai-contracts"]

[tool.uv.sources]
shosai-contracts = { path = "../contracts", editable = true }
```

```python
from fastapi import FastAPI
from shosai_contracts import Candidate, CompatClass, Scope, check, load_baseline, render_text


def test_the_app_keeps_the_native_contract(app: FastAPI) -> None:
    scope = Scope(classes=frozenset({CompatClass.NATIVE}), served_only=True)
    report = check(load_baseline(), Candidate(openapi=app.openapi()), scope)
    assert report.is_compatible, render_text(report, scope)
```

### Read the report

Each finding has a rule, the route or frame, a pointer into the schema, and a severity. Severity combines how dangerous the change is with who uses the route:

| | `native`, `external` | `web` | `unused` |
|---|---|---|---|
| **breaking**: the client will fail or lose data | error | warning | info |
| **risky**: the client may fail; a person must look | warning | info | info |

Only errors fail the check. The rules are directional:

- **Request.** v2 must accept everything the draft accepted. A newly required property or parameter, a narrowed type, a rejected `null`, a removed enum value or variant, or a removed media type breaks. A property v2 stops reading is risky.
- **Response.** v2 must return only what draft clients can decode. A removed or no-longer-required property, a widened type (`integer` → `number`), a newly nullable value, a changed success status or a changed media type breaks. New enum values or union variants, and removed optional properties, are risky.
- **WebSocket.** A missing client frame or server frame breaks, and so do a field change by the same rules, a changed encoding or binary layout, a removed authentication mechanism, a changed discriminator, or a removed handshake status that clients react to. A removed close code is risky. New server frames are allowed: clients ignore unknown types (§10).

Rule names and texts are in `schema_rules.py`, `http_check.py` and `ws_check.py`. Error responses are not compared; see "Limits".

### Accept a deliberate deviation

When a change is intentional and safe, for example because a field no shipped client reads is removed, record it with its reason instead of weakening the check:

```json
{
  "format": "whisperer-contract-acceptances/1",
  "accepted": [
    {
      "id": "response.optional_property_removed GET /v1/me/sessions response.200.items[].legacy_flag",
      "reason": "No client reads legacy_flag (consumers.md); dropped with the v2 data model."
    }
  ]
}
```

Pass the file with `--accept`, or as the fourth argument of `check()`. The `id` is printed with every finding, and a reason is required. Accepted findings stay in the report as info. Acceptances that match nothing in the current scope are listed so stale ones can be removed.

### WebSocket catalogue format

```json
{
  "format": "whisperer-websocket-catalogue/1",
  "endpoints": [
    {
      "path": "/v1/ws/realtime",
      "discriminator": "type",
      "auth": ["header:authorization-bearer", "subprotocol:whisperer-bearer"],
      "query_params": [{"name": "sid", "type": "string", "required": true}],
      "close_codes": [{"code": 1008}],
      "handshake_rejections": [{"status": 403}],
      "frames": [
        {"direction": "client_to_server", "type": "hello", "encoding": "json",
         "fields": [{"name": "language", "type": "string", "required": false}]},
        {"direction": "client_to_server", "type": "<binary:audio-chunk>", "encoding": "binary",
         "binary_format": "u8 speaker (0 me, 1 them) + RIFF WAV, PCM16LE mono 16 kHz"}
      ]
    }
  ]
}
```

- `direction`: `client_to_server` or `server_to_client`.
- `encoding`: `json`, `binary` or `text`.
- `type` for a field: one of `string`, `integer`, `number`, `boolean`, `object`, `array`, `null` or `any`, joined with `|` for a union (`string|null`). Nested fields use dotted names.
- `auth` tokens used by the draft: `header:authorization-bearer`, `subprotocol:whisperer-bearer`, `subprotocol:whisperer-room-pass` and `none`.
- `binary_format` must match the draft's text exactly; a change in byte layout is a change in contract.

The draft's file adds documentation keys (`description`, `source`, `consumers`, `class`, `slice`). The parser ignores them in a v2 catalogue.

## Updating the baseline

The draft keeps serving production until cutover (M2), so it can still change. To refresh the baseline:

1. Build a throwaway environment for the draft. Use the draft's Python and its `requirements.txt`, and never its `.env`:

   ```bash
   uv venv --python 3.12 /tmp/draft-venv
   VIRTUAL_ENV=/tmp/draft-venv uv pip install -r /root/whisperer/backend/requirements.txt
   ```

2. Regenerate the OpenAPI document and the route table. `env -i` keeps host variables out, and the tool sets only local placeholder settings. It never starts the app's lifespan, so no database, Redis or network is touched.

   ```bash
   env -i PATH=/usr/bin:/bin HOME=/tmp PYTHONDONTWRITEBYTECODE=1 \
       /tmp/draft-venv/bin/python contracts/tools/generate_draft_baseline.py \
       --draft /root/whisperer --out contracts/draft
   ```

3. Classify every new route in `draft/consumers.json`, and catalogue every new frame in `draft/websocket.json`. Set the class and slice, give a reason for `external` and `excluded`, and list the call sites.
4. In `contracts/`, run `uv run shosai-contracts render`, then `uv run pytest`. The tests fail if a route is unclassified, if a route used by a shipped app is not `native`, or if a document is stale.

## Limits

- **Untyped responses.** 108 draft operations, including several `native` ones, declare no response schema, so their shape cannot be compared. They are listed at the end of [draft/consumers.md](draft/consumers.md). Their owning slice checks them against recorded responses (D2) and against the fields the clients read, which `consumers.json` lists where the agents could determine them.
- **Error responses** are not compared: the draft documents only FastAPI's 422. The `detail` rule above covers what native clients read.
- **Behaviour** is out of reach: a compatible shape can still return wrong data. Slice tests cover behaviour.
- **Consumers were found by reading code.** A URL assembled at run time in an unusual way may have been missed. Every call that matches no route is listed, which bounds the error from the other side.
- **The WebSocket baseline was derived from the draft's handlers, not from declared types.** v2 must export its catalogue from its own frame definitions, not copy this one.
